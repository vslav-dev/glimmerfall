# 02. Телеметрия игры в MegaApp ingest

Повод: на старом планшете поле не рисуется, игра при этом играется (цифры очков и похвала видны). DevTools нет — нужны логи с устройства на сервер.

## Задача
- Логи с любого устройства игрока → сервер, сразу видны владельцу.
- Новый дебаг-лог = правка кода + обычный деплой, без доработки инфраструктуры.
- Без изменений кода MegaApp: переиспользовать единый приём из плана 42 MegaApp (`megaapp-back/plans/42-extension-log-ingest.implementation-plan.md` — источник истины по контракту).

## Что есть в MegaApp
- POST `/api/ingest/<source>`, источники — env `INGEST_SOURCES` (имя:порог), ключи — `INGEST_KEYS` (общие на все источники), заголовок `X-Ingest-Key`.
- По ключу same-origin не проверяется.
- Хранение: NDJSON в `/root/megaback/data/ingest/<source>/`, ротация с zip-архивами.
- Контракт: `{events: [{id, stream, at, data}], dropped}`; ответ — подсчёт сохранённых/отвергнутых.

## Решения
- **Источник `glimmerfall`** — новая пара в `INGEST_SOURCES`, порог 100MB. Кода MegaApp не трогаем.
- **Ключ не в игре.** Игра публична: ключ в бандле = ключ ко всем источникам MegaApp. Поэтому nginx `gf.vslav.dev` проксирует единственный маршрут `/api/ingest/glimmerfall` на megaback (тот же сервер) и сам подставляет ключ из сниппета, который есть только на сервере.
- **Отдельный ключ** для игры в общем списке `INGEST_KEYS`: при утечке/шуме убирается, не задевая расширение.
- Веб-сборка шлёт same-origin — без CORS. Нативные оболочки шлют на абсолютный адрес; тело — строка (text/plain), то есть простой запрос без preflight; nginx отдаёт `Access-Control-Allow-Origin: *`, чтобы клиент видел статус.
- Анти-мусор: `limit_req` по IP, лимит тела 512 КиБ (как у бэка).
- `X-Client-ID` не шлётся (вызвал бы preflight). Уникальность `id` — случайный id сессии + номер; устройство — поле `device` в событии `session`.
- Dev-сборка не шлёт, печатает в консоль.

## Клиент
- Очередь в памяти, отправка пачкой через 2 с после события; сеть/5xx/429 → повтор через 30 с; 2xx/4xx → пачка закрыта.
- Лимит очереди 500, переполнение → счётчик `dropped` в следующей пачке.
- Уход со страницы (`visibilitychange`/`pagehide`) → `sendBeacon` остатка.
- Потоки: `session` (версия, UA, экран, dpr, устройство, список отсутствующих API), `gl` (WebGL-версия, GPU, лимиты текстур, потеря контекста), `error` (необработанные ошибки и rejections, одинаковые — не больше 5 за сессию), `debug` (точечные логи с тегом).

## Диагностика текущего бага
- Найдено: `ctx.roundRect` (Safari < 16, Chrome < 99) в отрисовке плиток/льда/ящиков. Заменён на построение через `arcTo`. Ключ атласа теперь запоминается после успешной отрисовки — сбой не оставляет поле с пустыми текстурами навсегда.
- Не до конца объясняет симптом (при исключении в старте уровня должна была остаться шторка), поэтому дебаг-логи:
  - `atlas`: размер холста, ключ (клетка@разрешение), альфа центра первого кадра (0 → не рисует 2D), время.
  - `frame-probe`: после пересборки поля — GL-ошибка и пиксель экрана в центре первой клетки (альфа 0 → текстура не дошла до GPU).
  - `session.missing` + `gl` — что умеет устройство.
- После выяснения причины — убрать `atlas` и `frame-probe`.

## Выкат (действия владельца, vps-31)
1. Сгенерировать ключ: 32 символа `[A-Za-z0-9]`.
2. `/root/megaback/.env.prod`: `INGEST_SOURCES=telemetry:1GB,hh-auto-otclicker:100MB,glimmerfall:100MB`; новый ключ дописать в `INGEST_KEYS` через запятую. `systemctl restart megaback`.
3. Сниппет `/etc/nginx/snippets/glimmerfall-ingest-key.conf` (права 600): `proxy_set_header X-Ingest-Key "<ключ>";`.
4. Конфиг из `deploy/nginx/gf.vslav.dev.conf` → `/etc/nginx/sites-available/glimmerfall`; `nginx -t && systemctl reload nginx`.
5. Push в `release` (деплой игры).
6. Проверка: POST на `https://gf.vslav.dev/api/ingest/glimmerfall` с тестовым событием → 200 `{"received":1,"stored":1,...}`; появился `/root/megaback/data/ingest/glimmerfall/`.
7. Чтение: `ssh vps-31 'cat /root/megaback/data/ingest/glimmerfall/*.ndjson' | jq -c 'select(.stream != "session")'`.
