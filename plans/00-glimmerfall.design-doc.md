# Glimmerfall — дизайн-документ (матч-3)

Рабочее название. Оригинальная матч-3: бесконечные процедурные уровни, адаптивная сложность, веб + Android + iOS из одной кодовой базы.

## 1. Цели и жёсткие критерии

- 60 FPS на слабых Android (2 ГБ RAM, Mali/Adreno начального уровня, WebView). Никаких фризов при каскадах.
- Отклик на свайп — визуальная реакция в том же кадре.
- Холодный старт: первый экран < 1 с на среднем телефоне, бандл < 300 КБ gzip без звуков.
- Быстро писать и править: горячая перезагрузка, логика проверяется тестами без рендера.
- Деплой: веб — статика (одна команда). Мобилки — нативная обёртка из той же сборки.
- Расширяемость: новый тип фишки / блокера / цели / бустера — один модуль + регистрация, без правки ядра.
- Звуки — заглушки, легко заменяемые файлами позже.

## 2. Стек

**Выбор: TypeScript + Vite + PixiJS v8 (WebGL) + Capacitor. Без UI-фреймворка.**

| Слой | Технология | Почему |
|---|---|---|
| Язык | TypeScript (strict) | Типы ловят ошибки до запуска, агенту проще править |
| Сборка | Vite | Мгновенный HMR, статический билд, минимум конфигурации |
| Рендер поля | PixiJS v8, WebGL-бэкенд | Батчинг спрайтов из одного атласа → единицы draw call'ов. Самый быстрый 2D на слабых WebView |
| UI (меню, HUD, оверлеи) | Обычный DOM + CSS поверх canvas | Вёрстка/адаптив/safe-area — силён CSS, правится за секунды. Анимации только `transform`/`opacity` (GPU) |
| Нативная обёртка | Capacitor | Та же веб-сборка → APK/IPA. Плагины: haptics, status bar, back-кнопка, пауза приложения, хранилище |
| Веб-оффлайн | PWA (manifest + service worker) | Установка на домашний экран, работа без сети |
| Тесты | Vitest | Ядро — чистый TS, тестируется в Node без браузера |
| Качество | `tsc --noEmit`, ESLint | По глобальным правилам |

**Отвергнутые варианты:**
- **Godot (обсуждали 04.11).** Для 3D/кроссплатформы годен, но для 2D-матч-3 в вебе: wasm-рантайм в десятки МБ → долгий старт на слабых телефонах, Safari капризен, петля «правка → проверка» медленнее, чем браузер + HMR. Выигрыша для 2D-головоломки нет.
- **Phaser.** Удобен для экшна (физика, сцены, тайлмапы) — всё это здесь не нужно. Тяжелее Pixi, собственный цикл и сцены мешают модели «логика отдельно, рендер — проигрыватель событий».
- **Голый Canvas 2D.** На слабых Android при сотнях частиц и масштабировании теряет кадры; WebGL-батчинг надёжнее.
- **Angular (как в соседних проектах).** Для игры с одним canvas и пятью экранами — лишний вес и change detection. Экраны — простые DOM-оверлеи, фреймворк не окупается. Сознательно не следуем образцу соседних проектов.
- **Unity / Cocos.** Тяжёлый веб-рантайм, медленная итерация, сложный деплой.

## 3. Бюджет производительности

- Один текстурный атлас для всех фишек, блокеров, частиц → поле рисуется за 1–3 draw call'а.
- Графика фишек генерируется процедурно при старте и при ресайзе под реальный размер клетки → чёткость на любом DPR, нулевой вес ассетов.
- Пулы объектов для фишек, частиц, всплывающих очков. В горячем цикле — ноль аллокаций.
- **Рендер по требованию:** тикер работает только пока есть активные анимации. В простое — 0 кадров (батарея, нагрев). Подсказка-шиммер запускает тикер на время анимации.
- DPR ограничен 2. Монитор времени кадра: при стабильных просадках — понижение уровня качества (DPR 1.5 → 1, меньше частиц, без тряски экрана).
- Никаких фильтров/блюра/масок в горячем пути. Свечение — запечённые в атлас спрайты с аддитивным смешиванием.
- Фон — статичный градиент (CSS или одна текстура), не перерисовывается.
- DOM-оверлеи во время хода не меняют лэйаут: счётчики обновляются текстом, без reflow соседей.
- Звук: короткие буферы, декодированные заранее; лимит одновременных голосов.

## 4. Архитектура

### 4.1 Главный принцип: логика мгновенна, рендер — проигрыватель

Ход игрока полностью разрешается в ядре синхронно (матчи → спецэффекты → гравитация → досыпка → каскады) и выдаёт **сценарий событий** (что исчезло, что куда упало, что появилось, какой спецэффект сработал, сколько очков). Вид проигрывает сценарий анимациями.

Плюсы:
- Ядро без таймеров и рендера → покрывается тестами, детерминировано (сидированный ГСЧ).
- Тот же движок гоняет ботов-симуляторов для оценки сложности уровня (раздел 7) — тысячи ходов в секунду.
- Скорость анимаций, пропуск анимаций, «быстрый режим» — меняются только в виде.
- Реплеи и отладка: сид + список ходов воспроизводят партию.

### 4.2 Модули

| Модуль | Ответственность | Зависит от |
|---|---|---|
| **Ядро (core)** | Модель поля, правила свапа, поиск матчей, спецфишки, блокеры, гравитация, досыпка, каскады, детект отсутствия ходов, перемешивание, сценарий событий. Чистый TS | — |
| **Контент-реестры** | Типы фишек, спецфишек, комбо, блокеров, целей, бустеров. Каждый — модуль с описанными хуками (реакция на матч рядом, на взрыв, на гравитацию и т. д.) | Ядро (интерфейсы) |
| **Генератор уровней** | Уровень из номера + параметров сложности: форма поля, цвета, блокеры, цель, ходы | Ядро, реестры, симулятор |
| **Симулятор** | Боты разной силы проходят уровень, оценивают вероятность победы | Ядро |
| **Директор сложности** | Модель навыка игрока, целевая вероятность победы, параметры генерации | Сохранение |
| **Поток игры** | Конечный автомат экранов и состояний партии | Все ниже |
| **Вид поля** | Pixi-сцена, проигрывание сценария, пулы, эффекты | Анимации, атлас |
| **Анимации** | Свой лёгкий твинер + очередь/таймлайн с параллельными и последовательными шагами | — |
| **Атлас** | Процедурная отрисовка графики в текстуру | Тема |
| **UI** | DOM-экраны и HUD, одна точка обновления из состояния | Поток игры |
| **Ввод** | Pointer events: свайп, тап-тап, блокировка во время проигрывания | Вид поля |
| **Аудио** | Событие → звук, громкости, разблокировка на первом тапе | Платформа |
| **Платформа** | Хаптика, пауза/возобновление, back-кнопка, safe-area, хранилище. Веб и Capacitor — две реализации одного интерфейса | — |
| **Сохранение** | Прогресс, звёзды, модель навыка, настройки. Версионированная схема | Платформа |

Связь между модулями — через типизированную шину событий (ход сделан, уровень выигран, спецфишка сработала…). Аудио, хаптика, аналитика, ачивки подписываются, не трогая ядро.

### 4.3 Расширяемость

- Новая спецфишка/блокер/цель = модуль в реестре + графика в атласе + звук в карте. Ядро не меняется.
- Комбо спецфишек — таблица «пара типов → эффект», а не ветвления.
- Генератор знает о контенте только через реестр (вес, с какого уровня доступно, «стоимость сложности»).
- Будущее (не в v1): бустеры, ежедневный уровень (сид = дата), события, облачное сохранение, музыка, локализация.

## 5. Геймплей

### 5.1 Поле и ход
- Поле до 9×9, обычно 8×8; формы с «дырами» (процедурные/шаблонные, симметричные).
- 4–6 цветов. Каждый цвет — уникальная форма (круг, капля, ромб, звезда, квадрат, шестигранник) → доступно дальтоникам.
- Ход: свайп на соседнюю клетку или тап → тап. Неудачный свап — возврат с лёгкой «пружиной».
- Нет ходов → анимированное перемешивание (гарантирует ≥1 ход и отсутствие готовых матчей).
- Подсказка после 5 с бездействия.

### 5.2 Матчи и спецфишки
| Фигура | Результат |
|---|---|
| 3 в ряд | Обычное удаление |
| 4 в ряд | Линейная (чистит ряд/столбец по направлению свапа) |
| L / T | Бомба (3×3) |
| 2×2 квадрат | Искра — летит к самой полезной для цели клетке |
| 5 в ряд | Призма — удаляет все фишки цвета, с которым свапнута |

Комбо спецфишек (свап двух спецфишек): линия+линия = крест; линия+бомба = три ряда и три столбца; бомба+бомба = 5×5; призма+спец = все фишки цвета становятся этим спецом; призма+призма = очистка поля. Таблица расширяема.

Каскады дают множитель очков и повышают тон звука на каждом шаге цепочки.

### 5.3 Блокеры (вводятся постепенно)
- **Лёд** (1–2 слоя) под фишкой — снимается матчем на клетке.
- **Ящик** — занимает клетку, ломается матчем рядом (1–3 прочности).
- **Цепь** — фишка не двигается и не свапается, снимается матчем с ней.
- **Дыры** — форма поля.

### 5.4 Цели уровня (одна или две)
- Набрать очки.
- Собрать N фишек цвета(ов).
- Снять весь лёд.
- Сломать все ящики.

Лимит ходов. Звёзды 1–3 по очкам. Победа → оставшиеся ходы превращаются в спецфишки, которые срабатывают (финальный «фейерверк», можно пропустить тапом).

Поражение → однократно «+5 ходов» бесплатно (в v1 без монетизации; сигнал для директора сложности).

## 6. Экраны и переходы

| Экран | Содержимое |
|---|---|
| Загрузка | Логотип, генерация атласа (доли секунды), прогресс не нужен если < 300 мс |
| Титул | Название, анимированные фишки на фоне, «Играть — уровень N», настройки |
| Карточка уровня | Номер, цели с иконками, ходы, «Старт». Новая механика → короткая подсказка |
| Игра | Верх: ходы, цели со счётчиками, шкала очков со звёздами, пауза. Центр: поле |
| Пауза | Продолжить, заново, настройки, в меню |
| Победа | Звёзды по одной с хлопком, очки со счётчиком, «Дальше» |
| Поражение | Прогресс целей, «+5 ходов» (один раз), «Заново», «В меню» |
| Настройки | Звук, музыка, вибрация, сниженное движение, сброс прогресса |

Переходы:
- Между экранами — короткое затемнение/шторка (≤ 300 мс), только opacity/transform.
- Вход на уровень — фишки падают сверху столбцами с задержкой волной.
- Выход после победы — поле разлетается/растворяется, сразу карточка следующего уровня (минимум тапов между уровнями: «Дальше» → карточка → «Старт»; опция авто-старта).
- Back-кнопка Android: игра → пауза; меню → выход с подтверждением.
- Сворачивание приложения → автопауза, сохранение состояния партии (продолжить с того же места).

Ориентация: портрет основной; ландшафт поддержан (HUD сбоку). Safe-area учитывается.

## 7. Генерация уровней (бесконечная)

### 7.1 Детерминированность
- Сид уровня = номер уровня (+ версия генератора). Уровень N у игрока всегда тот же при повторе — честность.
- Параметры сложности фиксируются при первом входе на уровень, хранятся в сохранении.

### 7.2 Параметры
Директор сложности выдаёт «бюджет сложности» уровня, генератор тратит его на рычаги:
- число цветов (самый сильный рычаг: 4 — легко, 6 — тяжело);
- форма поля (компактная — сложнее);
- тип и объём цели;
- плотность и прочность блокеров;
- число ходов (тонкая подстройка в конце).

### 7.3 Конвейер
1. Выбрать архетип уровня по ритму (см. 7.4) и доступным механикам.
2. Сгенерировать форму: шаблон из библиотеки или процедурно (симметрия по вертикали), проверка связности.
3. Расставить блокеры по паттернам (симметричные кластеры, ряды, рамки), а не шумом.
4. Начальная заливка без готовых матчей, с ≥1 ходом.
5. Задать цель исходя из поля (собрать цвет — пропорционально площади и ходам).
6. **Калибровка симулятором:** бот «средний игрок» (жадный по ценности хода с шумом) проходит уровень K раз с разными сидами досыпки. Бинарным поиском по числу ходов добиться целевой вероятности победы от директора. Бюджет — до ~100 мс, при необходимости в Web Worker во время экрана победы предыдущего уровня (предгенерация).
7. Валидация: уровень проходим лучшим ботом; иначе перегенерация.

### 7.4 Ритм кривой
- Пилообразная кривая: рост на 4–6 уровней → «тяжёлый» уровень (помечен) → 1–2 лёгких «отдыха».
- Новая механика вводится на облегчённом уровне с подсказкой, затем вплетается в общий пул.
- Ориентир ввода механик: лёд ~5, ящики ~12, цепи ~20, двойные цели ~30, дальше комбинации и рост прочности.
- Смена визуальной темы (палитра фона) каждые 20 уровней — ощущение прогресса.

## 8. Адаптивная сложность

### 8.1 Сигналы
- Победы/поражения подряд, число попыток на уровень.
- Запас ходов при победе (много осталось → легко).
- Прогресс цели при поражении (почти дошёл → близко к балансу).
- Использование «+5 ходов».
- Выход из уровня до конца (фрустрация).

### 8.2 Модель
- Рейтинг навыка игрока — скользящая оценка, обновляется после каждой попытки: насколько исход отличался от прогноза симулятора.
- Целевая вероятность победы = базовая кривая(номер уровня, ритм) + поправка:
  - серия поражений → цель растёт (помощь), ступенчато, с ограничением;
  - лёгкие победы с большим запасом → цель снижается;
  - коридор: 35–90 %, «тяжёлые» уровни ниже, «отдых» выше.
- Эффективная сила игрока смещает бота-калибровщика: уровень калибруется под «этого» игрока.

### 8.3 Рычаги на повторе уровня
- Форма и блокеры фиксированы (уровень узнаваем).
- После 2+ поражений подряд — мягкая помощь: +ходы, на 3-м — минус цвет при сохранении формы.
- Скрытый рычаг «удачи» в досыпке (небольшой уклон к полезным цветам при застревании) — слабый, с потолком, только в режиме помощи.

### 8.4 Принципы
- Помощь незаметна и ограничена — победа ощущается заслуженной.
- Никогда не усложнять внутри уже начатой попытки.
- Все решения директора логируются в дебаг-панели (для настройки).

## 9. Визуальный стиль

- Оригинальный стиль: мягкие «стеклянные» фишки с бликом и тенью, сочная, но не кислотная палитра; каждая форма уникальна.
- Тёмно-цветной градиентный фон с лёгкой виньеткой; поле — полупрозрачная подложка со скруглением.
- Все визуальные параметры (палитра, скругления, длительности, кривые) — в одном файле темы.
- Шрифт — один, округлый, подгружается локально.

### Анимации (ориентиры)
| Событие | Анимация | Длительность |
|---|---|---|
| Касание фишки | Лёгкое увеличение | 80 мс |
| Свап | Встречное движение, ease-out | 150 мс |
| Неудачный свап | Туда-обратно с пружиной | 220 мс |
| Матч | Вспышка + сжатие в ноль + искры | 180 мс |
| Падение | Ускорение + приземление со squash&stretch | ~60 мс/клетка, ≤ 350 мс |
| Появление спецфишки | Слияние фишек в точку + блик | 200 мс |
| Линия / бомба | Луч / волна + лёгкая тряска (если не отключено) | 250–350 мс |
| Каскад ×3+ | Всплывающая надпись похвалы | 600 мс |
| Очки | Всплывающая цифра над матчем | 500 мс |
| Звёзды на победе | По одной, хлопок + частицы | 3×250 мс |

- Перекрытие шагов: следующий каскад начинает падать, пока предыдущие частицы догорают — ощущение скорости.
- Множитель скорости анимаций в настройках разработки; «сниженное движение» — без тряски и с меньшим количеством частиц.
- Хаптика: лёгкая на матч, средняя на спецфишку, двойная на победу.

## 10. Звук

- Менеджер звука: событие игры → идентификатор звука → буфер. Карта в одном месте.
- v1: процедурно синтезированные заглушки (Web Audio): клик, свап, матч (тон растёт с каскадом), спец, взрыв, победа, поражение, кнопка UI.
- Замена на файлы — правка карты, код не меняется.
- Раздельные громкости: эффекты / музыка. Разблокировка аудиоконтекста на первом касании (iOS). Пауза при сворачивании.

## 11. Сохранение

- Прогресс (текущий уровень, звёзды по уровням), модель навыка, зафиксированные параметры уровней, настройки, снапшот текущей партии.
- Веб — локальное хранилище; натив — хранилище Capacitor. Один интерфейс.

## 12. Деплой
