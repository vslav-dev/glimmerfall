# Глубокий профиль производительности (22.11.2026)

## Задача
- Найти точную причину остаточных медленных кадров (~2% на 0.25.1 против ~0,3% до бонусов).
- Шире: ответить, всё ли сделано для скорости, — замерами, а не догадками. Найденное по пути — чинить.

## Что уже меряется (plans/03, plans/10)
- Окно perf на уровень: интервалы кадров (p10…p99, >20/33/50/100 мс), CPU кадра (update, render), draw calls, LoAF, Event Timing, ops, куча.
- Флаги-кадры (зарядка, готовый бонус, свечение, прицел), взрывы по видам, пик частиц, батарея.
- Слепые зоны:
  - какой ресурс узкий в конкретном медленном кадре: GPU, главный поток до кадра, наш JS, DOM;
  - сколько пикселей рисуется за кадр (заливка — главный подозреваемый на Mali при dpr 3);
  - сколько кадров рисуется впустую;
  - флаги считают кадры, но не медленные кадры под флагом — связь не видна;
  - DOM-анимации HUD (счётчики, похвала) не видны вовсе.

## Что меряем (новое)
- **Профиль медленного кадра:** средние update, render, опоздание кадра, заливка, спрайты, частицы, отставание GPU — отдельно для медленных (>20 мс) и обычных кадров. Разница показывает узкое место.
- **Опоздание кадра:** насколько колбэк кадра начался позже начала кадра — главный поток занят до нас (DOM, GC, чужие задачи).
- **Отставание GPU (WebGL2):** забор после каждого рендера; через сколько кадров GPU его прошёл. ≥2 — упор в GPU.
- **Заливка:** площадь всех видимых спрайтов плюс очистка холста, в долях холста; гистограмма и доля медленных кадров по корзинам заливки.
- **Пустые кадры:** кадры, где из анимаций остались только паузы-ожидания: рисовать нечего.
- **Флаги с медленными кадрами:** для каждого флага — кадры и медленные кадры под ним.
- **DOM-активность:** флаги «катится счётчик HUD», «показана похвала».
- **A/B на устройстве:** в меню эффектов — выключатели DOM-эффектов (поп счётчиков, похвала, свечение бонуса); выключенные эффекты пишутся в окно perf.

## Что чиним сразу (найдено чтением кода)
- Кадры без видимых изменений (только паузы) больше не рисуются: цикл идёт, GPU отдыхает.
- Счётчики HUD писали текст каждый кадр прокрутки, даже без смены числа, — пишут только при смене.
- Перезапуск CSS-анимаций через принудительный reflow (`offsetWidth`) на каждом шаге каскада (поп счётчика, похвала) → Web Animations API без reflow.

## Кандидаты на потом (решать по новым данным)
- Холст размером с поле (+поля для эффектов) вместо всей сцены: меньше очистки и композитинга.
- Непрозрачный холст с фоном внутри: композитору не смешивать полноэкранный слой.
- Потолок частиц и размеры больших аддитивных вспышек.
- Ограничение частоты кадров для спокойных анимаций (подсказка) на 120 Гц.

## Как читать новые окна (22.11.2026)
- `profile.slow` против `profile.fast`:
  - `late` заметно больше → главный поток занят до кадра (DOM, GC, чужие задачи): смотреть `flags` hudRoll/flashText и A/B выключателей;
  - `update`/`render` больше → наш JS;
  - `fill`/`sprites` больше, остальное то же → заливка, упор в GPU;
  - всё одинаково → время вне страницы: композитор, нагрев, троттлинг (сверять с `battery`, `flags.charging`).
- `gpuLag`: основная масса в 0 → GPU успевает; сдвиг в 2+ → GPU не успевает.
- `fillBins`: доля медленных по уровням заливки растёт → заливка виновата; ровная → нет.
- `flags.<имя>.slow / frames` против общей доли медленных → вклад состояния.
- `idle`: сколько кадров теперь не рисуется (паузы).
- `fxOff`: окна с выключенными эффектами для A/B на одном телефоне.
